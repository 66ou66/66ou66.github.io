开博第一篇:为什么写博客 ​

2026-10-25

博客开张了。第一篇文章不讲技术,讲清楚两件事:我为什么要写,以及打算怎么写。

为什么写 ​

对内的原因有三个,按重要性排:

  1. 倒逼理解。一个东西"能讲清楚"和"能用"是两回事。写作是最好的检验手段,所有"以为懂了其实没懂"的地方,写的时候都会暴露出来。
  2. 个人知识库。半年前怎么解决的那个诡异问题,我一定会忘。自己的文章是回查成本最低的方式。
  3. 梳理体系。零散的知识点只有写出来才会串成结构。

对外的原因很简单:一篇有深度的排查文章,是普通程序员成本最低的"作品集"。它还能把面试引导到我熟悉的领域——文章写在哪里,面试就聊哪里。

打算怎么写 ​

给自己立几条规矩:

  • 写过程,不写结论。"最后用了方案 B"没有价值,"为什么排除了方案 A、中间错过了什么线索、怎么定位到根因的"才有价值。弯路也是文章的一部分。
  • 趁热写。问题解决完当天或周末就写,拖过两周细节就忘光了。
  • 先发布,再迭代。不憋完美文章,写完就发,回头有新理解再改。
  • 月更,但不水文。一个月一篇有含量的,好过一周一篇流水账。

这个博客本身 ​

这个站是用 VitePress 搭的,托管在 GitHub Pages 上,源码在 GitHub。写作流程:本地 npm run dev 实时预览,写完 npm run deploy 发布。

搭建的完整过程——包括一次被 GitHub 拒绝的推送——写在下一篇文章:我是怎么搭建这个博客的。

以后每解决一个值得记的问题,这里就会多一篇。
